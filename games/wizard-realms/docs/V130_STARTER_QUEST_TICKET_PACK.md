## Public interface and stage rules

Add a pure `surveyorCrossingQuest(...)` view helper, consuming only `WizardViewProjection`, saved `greenwayWorks`, `riverBridgeIds`, and `claimedBridgeheadId` or an equivalent existing immutable projection. Return `{id, title, stage, objective, reward, complete}`. Stable ID `surveyor-first-find/v1`. Stages: gather logs for an accessible supported bridge, build that bridge, cross to its dry far-bank post, claim the find, complete. Both canonical Greenway creek and connected-river bridges qualify, and any canonical `claimedBridgeheadId` completes the quest. The north ladder and distant river are the next arc, not a required detour in this first quest. If the current V34 save has already reached a later stage, derive that stage immediately without replaying earlier prompts. Bridge IDs must be canonical, never guessed from arbitrary scene markers. If the player is elsewhere, the stage remains coherent and offers a return route. The existing claim preview decides which final reward is available; after claim, do not infer the historical pick-or-coins branch from present inventory or balance.

Expose one compact, collapsible quest surface in the existing objective region or HUD. It must not add a fixed overlay that covers Works or the avatar. The journal should make a novice's next action obvious and show why it matters. Keep the existing checked claim button as the only way to claim. The rest of the UI and V33/V32 remain behavior-identical. This can be delivered as a new pure view helper plus minimal controller and HUD wiring; if that exceeds 5 files or 300 net lines in one implementation lane, stop and replan.
