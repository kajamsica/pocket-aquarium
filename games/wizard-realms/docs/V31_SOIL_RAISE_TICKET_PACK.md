# V31 checked soil placement

## Outcome and scope

Let a new player use an equipped spade to click revealed dry ground and place one carried soil unit as a walkable 0.4 m lift. Digging that placed lift returns exactly one soil without XP or geology; digging again reaches the original stratum. The saved, simulated, picked, and rendered height must be the same. This is the first bounded above-grade terrain step, not arbitrary Minecraft-height stacking.

Keep the existing V30 preview and saves unchanged. Expose this only through a new opt-in V31 route after its migration, witness replay, and UI journey pass. Do not modify a V30 root in place or silently upgrade old saves. The V31 source pins a complete checked V30 root (`lineage`, `head`, and `previous`), including its V29 ancestry, then creates an empty raised-cell sidecar.

## Fixed interface contract

- V31 progress adds `raisedSoilCells: readonly { gx: number; gz: number }[]`, sorted, unique, maximum 256, using canonical world-grid coordinates. Each cell is 0 or 1 lifted layer. The underlying V26 `terrain.columns` and geology rewardDepth retain their exact schema and meaning.
- New canonical checked witnesses identify one `gx,gz` and action, `soil-place/v1` or `soil-remove/v1`. The UI may label remove as Dig. Existing V30 witnesses must replay with the sidecar unchanged. Each successful lift subtracts one `terrain.bag.soil`; each removal adds one, with capacity checked. No XP, event reward, or geologic stratum is minted for these actions. A normal Dig on a raised cell must remove the lift first, not hit native geology.
- An eligible placement cell is revealed, dry, original-grade (`openDepth = 0`), not already raised, in 5 m reach from a grounded spade-equipped player, not beneath the player, store, camp, resource, built Works, bridge, ladder, river, or other protected route. Reject blocked or malformed targets before a checked write. Removal also rejects an underfoot cell and requires a raised cell and bag capacity, so it never strands a saved pose above removed support. Reuse the stricter current bridge-footprint occupancy rule, not only V26's older helper.
- Effective top height is native support plus 0.4 m for a raised cell. Movement and pose validation must use this same support; a normal 0.4 m rise is traversable, but raising one cell does not waive 0.8 m dry-bank, cliff, wet-river, or built-route gates. Rendered terrain top, edge transitions, target outline, HUD status, and map cell truth must match support. A raised cell cannot be a floating visual or a hidden collidable wall.
- All V31 root reads validate pinned V30 source, structural material conservation (including raised soil), previous/head revision, deterministic replay of all witness types, and a checked compare-and-swap write. Return Home, frame autosave, purchases, store sales, bridging, mining, and prior V30 actions remain available with explicit V31 preservation. On any uncertain handoff, fail closed to the existing full replay, never accept a client assertion as authority.
- Browser access is a milestone, not completion. Run one renderer only. The V30 preview remains available and unchanged while V31 is developed.

## Abort and replan conditions

If support projection cannot be extended without modifying old-version authority, stop the V31 code lane and redesign the overlay boundary. If a soil lift changes a route gate, makes previously dry land wet, allows duplicate soil or reward XP, or breaks V30 reload, revert only the scoped V31 edit and replan. Do not present a render-only mound as working terrain. Do not run multiple WebGL renderers or broad parallel test suites while the UI journey is open.
