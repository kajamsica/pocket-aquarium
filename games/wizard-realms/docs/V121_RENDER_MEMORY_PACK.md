# V121: Wizard scene movement-memory gate

## Outcome and boundary

Make extended exploration safe in one browser renderer while preserving the checked V33 save/reload and V32 behavior. The immediate acceptance gate is an authentic migrated V33 profile that can move toward and discover the Mireglass ring, save, close, and reopen without exceeding a 1,000 MiB exact-renderer RSS watchdog. This does not declare fairy-ring travel complete. Keep the user-facing V32 preview on 5193 and opt-in V33 on 5194 available; only one automated browser renderer may run at once. No GitHub action, commit, deployment, or PR is authorized in this pack. Preserve all dirty worktree state and private save data.

## Observed failure and confirmed exclusions

The authentic V33 save is playable at Mireglass. M10 removed unnecessary post-keyrelease neutral-frame padding; the real UI saved a short walk and reopened the same private profile at V33 save #1, retaining Level 16 and 182 coins. A longer two-step approach toward the ring later peaked at 1,022,880 KiB, only 1,120 KiB below a 1,024,000 KiB watchdog, so the tester stopped. Discovery and travel are unproven.

The checked store is not a demonstrated movement-allocation owner. A codec-faithful, strictly decoded copy of the authentic U5 record ran 64 movement and neutral frames through the complete V23-to-V33 projection chain with RSS staying below 462,000 KiB, zero rejections, and zero writes. In Chromium the corresponding movement caused renderer RSS to rise hundreds of MiB; GPU-process RSS stayed nearly flat. CDP showed used/total JS heap and event-listener counts surging transiently, then falling after GC while renderer RSS stayed high. The current source has one persistent Canvas and content-signature guards on heavy geometry. `UnchartedTerrain` remounts an instanced fog mesh when hidden-cell count changes, but its bounded size does not by itself explain the observed rise. No specific React/Three allocation owner is confirmed.

## Tickets and sequencing

Open only one isolated V33 renderer. Before scene entry, bind the exact browser/renderer PIDs and arm a 50 ms watchdog at 1,024,000 KiB. Capture a low-overhead CDP sampling allocation profile during one bounded 0.25-0.5 second movement and at most 2 seconds after release, stopping sampling before the guard trips. Record top allocation stacks and counts without media or save contents. Also record renderer/GPU RSS, used and total JS heap, pending-frame/save phase, Canvas identity, and whether allocations continue after key release. If profiler overhead pushes RSS near the guard before an attributable sample, stop and report inconclusive rather than disable the guard. Do not take a heap snapshot or open a second renderer. No source edits, raw checkpoint output, GitHub, commit, or nested worker.

Propose one falsifiable bounded repair, or a render-architecture partition if the source crosses the 300-net-line tripwire. Do not label a source-only hypothesis a measured leak.

### V121-C: one grounded repair

If A/B cannot identify a bounded owner, stop this ticket and replan the renderer architecture explicitly.

### V121-D: identical user journey

Role: UI tester, after C. From a private persistent authentic V33 save, repeat the same movement input, then continue in bounded steps until the Mireglass discovery control appears. Save, close, reopen the same profile, and verify discovery persists. Use one renderer at a time, an exact-PID 1,024,000 KiB watchdog, and no screenshot/snapshot near its limit. ### V121-R: independent review

Role: read-only reviewer after C/D. Findings first. Decide whether V33 can leave guarded opt-in development, with explicit pass/fail for memory, save/reload, ring discovery, two-way travel, post-arrival movement, and V32 compatibility. No final GO from source-only evidence.

## Stop and replan rules

Do not repeat browser traversal while memory reaches the guard without new allocation evidence. If one measured bounded repair does not improve the identical journey, or the owner spans shared scene architecture, create a scoped architecture partition with explicit migration and visual-parity proof rather than layering speculative local patches. Keep all private checkpoints/profiles mode 600/700 respectively, never print or commit their contents, and close every owned renderer after a probe.
