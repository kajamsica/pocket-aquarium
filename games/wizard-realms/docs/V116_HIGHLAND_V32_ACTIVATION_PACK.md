# V116: activate Highland Quarry on the checked V32 path

## Outcome and scope

The current public V31 game can cross east from Greenway and render Highland terrain, but cannot discover Quarry Crown, extract the four canonical stone nodes, or complete a Highland source-to-buyer loop. The older V11 game has those mechanics, but is not the active V31 save lineage. V32 must make the next connected region playable without changing V11 or V31 history, moving the player artificially, or weakening checked replay.

The first V32 milestone is a genuine, legible eastward trip: follow a discoverable trail from Greenway, study Quarry Crown on foot, extract at least one canonical node with an equipped spade and Excavation Lv2, retain the changed node and inventory through save/reload, return west on walked ground, and sell stone at Greenway Outfitters. The separate Windward Step spell, fuller quarry dressing, and longer campaign follow only after this loop is independently proved. This is not the full-game terminal condition.

## Locked interface and authority contract

- Create a distinct `wizard-world/v32` checked store that pins the complete validated V31 source root. Keep source roots, IDs, seeds, old URLs, and all V31 witness meanings unchanged. A new fresh V32 world may build its predecessors explicitly; existing V31 players get a non-destructive copy choice. Do not silently reset or modify a source save.
- `PublicV32Progress` has the V31 progress fields. Highland state is already in `state.highland`; do not duplicate it in a second ledger. New witnesses are exactly `{ kind: 'highland-discover/v1', landmarkId: HIGHLAND_LANDMARK.id }` and `{ kind: 'highland-extract/v1', nodeId: string }`. Existing V31 witnesses replay through the V31 authority and retain Highland state exactly. A new witness must reconstruct every changed byte of a V32 successor.
- Discovery is an explicit, checked `Study Quarry Crown` interaction while grounded and within the canonical landmark radius, after the landmark tile has been revealed by walking. It is idempotence-rejected, not a generic click anywhere. This avoids retroactively changing V31 frame semantics. Extraction is an explicit checked interaction within 3 m of one of `highlandStoneNodes(seed)`, with the tile revealed, Crown studied, owned and equipped field spade, Excavation Lv2, room for two stone, and node recovery tick satisfied. Grant two stone and 20 Excavation/total XP, set `readyAtTick = tick + 3000`, and reject on overflow. Reuse the V11 economy and canonical node facts, but adapt discovery to the V14 mask and effective V31 pose. Failure returns unchanged progress and an actionable reason.
- Decode exact bounded shapes. Require canonical node IDs and sorted node ledger, correct seed and content revision, valid discovery mask, physical pose, bag capacity, monotonic landmark and node recovery, XP/material accounting, and preserved V31 terrain/works/river/mining/soil invariants. A forged successor with free stone, impossible landmark, altered source receipt, or inherited replay bypass must fail. For the three-slot local save format, additionally bound held stone by source-held stone, canonical post-migration one-shot stone rewards, and the maximum repeat extractions consistent with each node's last recovery tick. This catches a forged old previous with free stone and unchanged acquisition facts without rejecting honest repeat harvests. Browser storage is editable by its owner, so this is structural corruption resistance, not an anti-cheat guarantee. An online player market would require server authority or another external trust anchor.
- `replayPublicV32Witness(before, rawWitness)` accepts old V31 witnesses through `replayPublicV31Witness` and the two Highland witnesses through the new authority. `confirmPublicV32HighlandAction(before, witness)` returns either checked progress or a stable rejection. Controller runtime and writer must use the same replay function, not independently trust UI state.
- UI projection contract: `projectPublicV32WorldView(progress, carrier)` adds discovered-only east trail/quarry map cues, canonical Crown and stone outcrops only in active and discovered cells, nearest actionable interaction, clear locked/cooldown reasons, and westward return/sale guidance. Preserve existing Mireglass/Greenway projection and `visualWorld` terrain. No permanent omniscient markers or hidden-resource leakage. A Crown prompt must be visible before the action is possible.
- Controller/entry contract: `?publicWorld=v32` routes to V32 entry only after tests and review clear its readiness flag. V32 runtime wraps the V31 movement/action simulation, checkpoints pending frames before a Highland checked action, verifies the V32 writer reply, then reconstructs its core. Generic E can study/extract only the currently projected nearby Highland interaction. Explicit store sale remains through existing checked purchase/sale route. The entry button should say `Start new adventure` or `Continue adventure`, with the non-destructive save-copy detail in supporting text rather than its primary label.
- Keep the single live renderer discipline. Source/unit lanes may run in parallel. UI acceptance gets one isolated production preview and one browser renderer under about 1.2 GB RSS; close it after saving evidence. Do not print or commit private IndexedDB checkpoints.

## Ownership lanes

1. **Domain authority**: new V32 migration, witness/replay, Highland checked action, strict decoder and tests. Own only new `domain/publicWorldV32*` files. Publish exact exports/types early.
2. **Store and flow**: new `domain/atomicV32Database*` and `domain/publicWorldV32Flow*` files, plus tests. Use lane 1's locked exports. Own no shared controller or old version file.
3. **Projection**: new `PublicV32WorldView*` files and tests only. Use lane 1's progress type. Retain existing scene primitives, map contracts, and V11 reference geometry.
4. **Entry/controller integration**: new `PublicV32Entry*` and `PublicV32ControllerRuntime*`, targeted `main.tsx` and `PublicV23Controller.tsx` edits, plus focused tests. Integrate only after the domain/flow interfaces exist. Do not enable the public URL until unit, source review, and UI smoke pass.
5. **Independent review and UI proof**: separate read-only source review, then isolated production-preview travel with exact rejection/recovery and same-tab reload. Record a public evidence receipt and remaining risks.

## Acceptance and stop rules

Before UI exposure: red then green tests for valid discover/extract, all enumerated rejections, inherited witness parity, forged free stone in the current or old previous slot, honest repeated extraction from one recovered node, preexisting source stone, sale/trade, altered source, two principal seeds, V31-to-V32 copy and resume, prior-version isolation, no double action, and return-home parity. Run TypeScript and focused suites. A failed proof keeps V32 behind its readiness flag. Real UI must prove the east-to-west stone trade on a single genuine lineage, not a synthetic state jump. If the roughly 988 m path makes a full automated journey too expensive, identify that separately; do not claim a source-level proof is a played proof.
